## Запуск

Из корня репозитория в существующем окружении:

```bash
MPLCONFIGDIR=/tmp/cv-matplotlib conda run --no-capture-output -n mmpose \
  python tools/analyze_vertebrae_shifts.py \
  --annotations data/LumbarCoco2000/annotations \
  --output-dir reports/buu_vertebrae_shifts
```

`--annotations` принимает один или несколько JSON-файлов и/или директорий.
Директории обходятся рекурсивно. Для анализа всего датасета включите все split.
`--bins` задаёт число общих интервалов (по умолчанию 40).
Зависимости: стандартная библиотека, NumPy, matplotlib; загрузка MMPose не требуется.

```bash
conda run --no-capture-output -n mmpose python -m unittest discover \
```

## Определение

Три точки каждой пары: `P` — нижняя задняя точка верхнего позвонка,
`A` и `B` — передняя и задняя точки верхней пластины нижнего позвонка.
`Q` — основание перпендикуляра из `P` на бесконечную прямую `AB`.

```text
L = |B − A|
u = (B − A) / L
Q = A + dot(P − A, u) * u
S = dot(B − Q, u) / L = dot(B − P, u) / L
```

Положительное значение — переднее смещение задней точки верхнего позвонка
относительно задней точки нижнего; отрицательное — заднее;
ноль — совпадение задних краёв по проекции. Проекция за пределами отрезка
допускается. Модуль, обнуление отрицательных значений и ограничение диапазона
не применяются. Передняя точка верхнего позвонка не участвует.

Анатомический порядок `A → B` сохраняется при поворотах, без сортировки по X.
Порядок 22 keypoints взят из `configs/_base_/datasets/lumbar_coco.py`
и проверяется по категориям COCO. Индексы `(P,A,B)`:
(3,4,5), (7,8,9), (11,12,13), (15,16,17), (19,20,21).

`max_shift` — алгебраический максимум валидных знаковых значений,
а не максимум по модулю. Если все пять отрицательны, максимум отрицателен.
Если валидных значений нет, записывается `NaN`.

## Обработка данных

Для трёх используемых точек требуется COCO `v=2`. Отсутствующие,
неразмеченные (`v=0`), невидимые (`v=1`), нечисловые/нефинитные точки,
выход за границы исходного снимка, нулевая длина `AB` и crowd дают `NaN`.
Невалидные точки вне используемой тройки не влияют на расчёт пары.
В JSON сохраняются причины и идентификаторы невалидных измерений;
отсутствующие статистики представлены стандартным `null`.

Снимки объединяются по `file_name` с проверкой ID и размеров. Одинаковые
keypoints/category/iscrowd считаются одной аннотацией. Разные аннотации
одного снимка дают пять `NaN`; конфликты метаданных и неверный порядок
keypoints останавливают запуск с ошибкой.

Стандартное отклонение: `ddof=0`; процентили: линейная интерполяция;
счётчики превышений: строгое `>` по неокруглённому порогу.
Все три графика используют одинаковые интервалы, включающие отрицательные
и положительные значения; ноль отмечен вертикальной линией.
