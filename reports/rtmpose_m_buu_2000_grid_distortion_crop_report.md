## Аугментации и pipeline

Вместо сдвига части позвоночника используется `LumbarGridDistortion`: нелинейная деформация сетки изображения с согласованным преобразованием ключевых точек, затем случайный crop по обновлённой разметке.

| Параметр | Значение |
|---|---|
| `num_steps` | 5 |
| `distort_range` | (-0.05, 0.05) |
| `normalized` | True |
| Вероятность grid distortion `p` | 0.5 |
| `keypoint_remapping_method` | mask |
| Вероятность crop `apply_prob` | 0.8 |
| Статистика crop | `reports/vertebrae_statistics_train.json` |

Диапазон ±0.05 задаёт параметры деформации сетки, а не гарантированное смещение каждой точки на 5% размера изображения. По текущей реализации используется Albumentations GridDistortion; имя `distort_range` адаптируется к поддерживаемому API (`distort_limit` в Albumentations 2.0.8). Версия Albumentations фактического запуска в журнале не зафиксирована.

```text
Train: LoadImage → FullImageBBox
       → LumbarGridDistortion(num_steps=5, distort_range=±0.05,
                              normalized=True, p=0.5, remapping=mask)
       → GetBBoxCenterScale(padding=1.0)
       → RandomVertebraeCrop(apply_prob=0.8)
       → TopdownAffine(256×512) → GenerateTarget → PackPoseInputs

Val/test: LoadImage → FullImageBBox → GetBBoxCenterScale(padding=1.0)
          → TopdownAffine(256×512) → PackPoseInputs
```

Grid distortion применяется к исходным пикселям и точкам до финального affine. Crop задаёт центр, масштаб и поворот; само вырезание выполняет `TopdownAffine`. На validation/test случайных деформаций и crop нет; используется полный снимок без вычисления bbox по GT-точкам.

По текущему коду mask remapping повторяет выбор сетки до трёх раз при потере точек, затем оставляет исходный образец с предупреждением. Поэтому `p=0.5` — вероятность попытки преобразования. Seed Albumentations устанавливается из NumPy RNG на каждое применение. Это описание текущего кода: сохранённый конфиг не архивирует версию реализации и внешнюю статистику на момент запуска.

Сохранённый конфиг отличается от modified shift + crop импортом и train pipeline (включая копию в dataloader), а также `work_dir`. Модель, оптимизация, EMA, seed, val/test pipeline и остальные настройки совпадают. Исходный файл в `configs/` содержит `OptimWrapper` и только EMA hook; **фактический запуск использовал `AmpOptimWrapper(loss_scale='dynamic')` и дополнительный `AugmentationComparisonHook(count=5)`**. Для воспроизведения следует брать сохранённый конфиг запуска.

## Сравнение экспериментов

Для каждого рецепта указан checkpoint, выбранный по его validation.

| Рецепт | Лучшая эпоха | Лучший validation | Test | Правильных точек test |
|---|---:|---:|---:|---:|
| Только crop | 200 | 88.4545% | 90.0000% | 3960 / 4400 |
| Shift + crop | 180 | 90.3182% | 90.5909% | 3986 / 4400 |
| **Grid distortion + crop** | **200** | **91.2955%** | **91.3409%** | **4019 / 4400** |
| Modified shift + crop | 200 | **91.9545%** | **92.7045%** | **4079 / 4400** |

Относительно crop: лучший validation **+2.8409 п.п.** (125 точек), test **+1.3409 п.п.** (59 точек). Число test-точек вне порога снизилось с 440 до 381 — на **13.41%**.

Относительно исходного shift + crop: validation **+0.9773 п.п.** (43 точки), test **+0.7500 п.п.** (33 точки).

Относительно modified shift + crop: validation **−0.6591 п.п.** (29 точек), test **−1.3636 п.п.** (60 точек). Число test-точек вне порога выше: **381 против 321**, или на **18.69%**.

Grid + crop улучшил результат относительно crop, однако modified shift + crop остаётся лучшим среди этих четырёх рецептов. Один seed не позволяет оценить устойчивость разницы или статистическую значимость. Одинаковый seed при разных pipeline не гарантирует одинаковую последовательность crop; агрегатные метрики не показывают распределение ошибок по снимкам и позвонкам.

## Время, ресурсы и ранние запуски

Итоговый train-журнал: **03.11.2026 23:21:43 — 04.11.2026 01:50:35**, то есть **2 ч 28 мин 52 с**. Часовой пояс в журнале не указан, время приведено как записано. Это длительность завершённого запуска с инициализацией, validation и сохранением checkpoint; ранние попытки в неё не включены.

Максимальное записанное поле `memory` — **5901 MB**. Средние по записанным train-строкам: `time ≈ 1.668 с`, `data_time ≈ 1.450 с`; отношение средних — **86.9%**. Большая доля ожидания данных указывает на существенную стоимость подготовки batch, но не является изолированным профилированием grid distortion.

Modified shift + crop завершился за **1 ч 1 мин 43 с**: grid + crop занял примерно **в 2.41 раза больше времени** при более низком validation и test. Нагрузка системы между запусками могла различаться. Test-журнал фиксирует загрузку checkpoint в 01:50:54 и завершение в 01:50:55; эти отметки не измеряют задержку одного снимка.

- `20261103_012002` и `20261103_013203`: журналы заканчиваются после инициализации; записанных train/val-метрик нет.
- `20261103_014606`: незавершённый запуск, последний текстовый train-log — эпоха 127, batch 10/25; последний корректный JSON train — итерация 3162. Validation записан до эпохи 120 (87.3636%). В конце log/JSON есть нулевые байты; одна строка JSON не разбирается. Причина остановки в сохранённых материалах не установлена.
- У раннего запуска `num_workers=0`, logger interval=1; у итогового — **8 workers**, interval=10. Параметры grid distortion в сохранённых конфигурациях совпадают. Среднее записанное время итерации раннего запуска — около 6.946 с против 1.668 с итогового; это наблюдение не изолирует эффект workers от остальных условий. Итоговый запуск стартовал заново (`resume=False`, `load_from=None`); метрики раннего и завершённого запусков не объединялись.

## Практический вывод

Для рецепта grid distortion + crop следует использовать **checkpoint эпохи 200**: **91.2955% validation / 91.3409% test**. По имеющимся данным grid distortion полезен относительно одного crop, но не превосходит modified shift + crop и требует примерно в 2.41 раза больше полного времени обучения. Для выбора устойчивого рецепта нужны повторения на нескольких seed; подбор вероятности и амплитуды grid distortion следует вести по validation, сохраняя test для итоговой оценки.
