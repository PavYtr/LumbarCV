Точка считается правильной при евклидовой ошибке **не больше 10% длины ее собственного GT-сегмента** — соответствующей замыкательной пластинки. Результат объединяется по всем допустимым точкам выборки. Это доля правильных точек, а не снимков; значение не является точностью в миллиметрах или COCO AP.

## Фактические настройки запуска

Основной источник — [сохраненный конфиг обучения](../work_dirs/rtmpose-m-lumbar-coco2000-vertebrae-shift-crop/20261102_175412/vis_data/config.py).

| Параметр | Значение |
|---|---|
| Модель | TopdownPoseEstimator, CSPNeXt-m + RTMCCHead, 22 точки |
| Вход | 256 × 512 пикселей, ширина × высота |
| Разметка targets | SimCC, split ratio 2, sigma (6, 9) |
| Инициализация | Предобученный CSPNeXt backbone; `load_from=None`, `resume=False` |
| Обучение | 210 эпох, 25 итераций в эпохе, batch 64, workers 8 |
| Validation / test | Batch 16, workers 4, 13 batch на выборку |
| Seed | 21 |
| Оптимизатор | AdamW, LR 0.0005, weight decay 0.05, clip grad norm 35 |
| AMP | AmpOptimWrapper, dynamic loss scale |
| Scheduler | Linear warmup 500 итераций; cosine на эпохах 105–210 до LR 0.000025 |
| EMA | ExpMomentumEMA, momentum 0.0002, update_buffers=True |
| Выбор checkpoint | Каждые 10 эпох, максимум LocalPCK/segment@0.1/PCK |
| Среда из журнала | Python 3.10.21, PyTorch 2.14.0+cu130, MMEngine 0.10.7 |
| GPU | Одна NVIDIA GeForce RTX 5070 Ti |

Train pipeline:

```text
LoadImage → RandomVertebraeShift(prob=0.5, max_shift_ratio=0.25)
          → FullImageBBox → GetBBoxCenterScale(padding=1.0)
          → RandomVertebraeCrop(apply_prob=0.8)
          → TopdownAffine(256×512) → GenerateTarget → PackPoseInputs
```

По [текущей реализации RandomVertebraeShift](../augmentations/vertebrae_shift.py) случайно выбирается один из пяти межпозвонковых промежутков L1–L2 … L5–S1. Верхняя относительно разреза часть изображения и соответствующие точки сдвигаются вдоль промежутка. Максимальное смещение — **25% длины отрезка разреза**, в любую сторону; при необходимости оно уменьшается для сохранения размеченных точек внутри изображения. Вероятность 0.5 — вероятность попытки преобразования: вырожденная геометрия и другие проверки могут привести к пропуску.

Кроп рассчитывается после сдвига по обновленным точкам и [статистике train](vertebrae_statistics_train.json). При его пропуске остается полный снимок. На validation и test используется одинаковый детерминированный pipeline: `LoadImage → FullImageBBox → GetBBoxCenterScale(padding=1.0) → TopdownAffine → PackPoseInputs`. Случайных сдвигов, кропов и вертикализации по GT при оценке нет. Grid distortion в сохраненном train pipeline отсутствует.

**Для воспроизведения важен сохраненный конфиг:** в разделе про этот запуск в `RUN_TRAINING.md` указано `max_shift_ratio=1.25`, тогда как сохраненный конфиг фактически выполненного обучения содержит **0.25**. В отчете используется значение из артефактов запуска. Снимок конфига не фиксирует содержимое внешнего JSON статистики и код аугментаций на момент обучения; описание механики выше проверено по текущему коду.

## Сравнение с предыдущими экспериментами

Для каждой модели ниже взят checkpoint, выбранный по ее validation; test не использовался для выбора эпохи.

| Запуск | Лучшая эпоха | Лучший val | Test | Test: правильных точек |
|---|---:|---:|---:|---:|
| Полный снимок без случайных аугментаций | 210 | 16.7727% | 16.8409% | 741 / 4400 |
| RandomVertebraeCrop | 200 | 88.4545% | 90.0000% | 3960 / 4400 |
| **RandomVertebraeShift + RandomVertebraeCrop** | **180** | **90.3182%** | **90.5909%** | **3986 / 4400** |

Относительно предыдущего запуска с кропом прирост составляет:

- **Validation: +1.8636 п.п.**, или **82 дополнительные правильные точки** при сравнении лучших checkpoint.
- **Test: +0.5909 п.п.**, или **26 дополнительных правильных точек**. Число точек вне порога уменьшилось с 440 до 414 — на 5.91% относительно прежнего числа ошибок.
- На общей эпохе 210 validation выше на **1.8182 п.п.**, или 80 точек.

Сверка сохраненных конфигов подтвердила одинаковые модель, оптимизатор, scheduler, seed, EMA, val/test pipelines и evaluators. Основное изменение train pipeline — добавление RandomVertebraeShift перед кропом. Новый конфиг самостоятельный и содержит metainfo внутри файла; предыдущий загружал его из отдельного файла. Есть также различия в оформлении scope, импортах и визуализации, поэтому конфиги целиком не идентичны. Исходные аннотации и код преобразований не архивировались внутри каждого снимка конфига.

В этом сравнении новый запуск улучшил обе отложенные метрики. Однако **один запуск с одним seed не позволяет установить устойчивость прироста** или статистическую значимость. Кроме того, добавленная аугментация меняет последовательность случайных чисел, поэтому одинаковый seed не обеспечивает одинаковых кропов в двух экспериментах. Отдельной оценки по пациентам, позвонкам и выраженности смещения нет; результат не доказывает улучшения именно на снимках со спондилолистезом.

## Время и ресурсы

По первой и последней временным отметкам train-журнала запуск занял **2 ч 56 мин 25 с**: `02.11.2026 17:54:13–20:50:38`. Часовой пояс в журнале не указан, время приведено как записано. Предыдущий запуск с кропом занял **28 мин 8 с**. Таким образом, полное время увеличилось примерно в **6.27 раза** при одинаковых 210 эпохах.

Максимальное записанное поле `memory` — **5901 MB**, столько же было у предыдущего запуска. Средние по записанным train-строкам: `time ≈ 1.990 с`, `data_time ≈ 1.770 с`, то есть около **89%** времени приходится на `data_time`. Это указывает на ожидание входного pipeline как вероятное узкое место. Это не профиль CPU/GPU и не измерение чистой стоимости RandomVertebraeShift: запуски выполнялись в разные дни, возможна разная нагрузка системы. Сама аугментация обрабатывает исходное изображение до уменьшения к 256×512, поэтому ее реализация — разумный объект для профилирования.

Test-журнал подтверждает загрузку лучшего checkpoint в `20:50:56` и завершение всех 13 batch в `20:50:57`. Эти отметки не являются измерением задержки инференса одного изображения.

## Практический вывод

Лучший checkpoint этого запуска дает **90.3182% на validation и 90.5909% на test**. Добавление сдвига сопровождается небольшим приростом test относительно кропа без сдвига, но существенно большим временем обучения. Для текущего результата следует использовать **эпоху 180**, а перед закреплением новой аугментации в основном рецепте — проверить повторяемость на нескольких seed и выяснить стоимость обработки исходных изображений. Для анализа оставшихся 414 ошибок на test потребуется расчет по отдельным точкам и снимкам: агрегатный JSON такую детализацию не содержит.
