## 2. Данные и постановка задачи

Использованы JPEG и соответствующие CSV из `BUU-LSPINE_2000/LA` — именно боковая проекция `LA`. Каталог `AP` в этот эксперимент не входит. В каждом CSV 11 строк вида `x1,y1,x2,y2,class`: две точки верхней и две нижней замыкательных пластинок L1–L5, затем две точки верхней пластинки S1. Поле `class` не является целевой переменной. Конвертер проверяет конечность координат и попадание в изображение, сортирует два конца каждого отрезка по `x` (меньший `x` — передний, `front`), присваивает всем 22 точкам COCO visibility `2` и создаёт одну аннотацию категории `lumbar_spine` на снимок.

Порядок выходов модели: для каждого L1–L5 — `TF`, `TB`, `BF`, `BB`, затем `S1TF`, `S1TB`. Буквы означают `T`/`B` = верхняя/нижняя пластинка, `F`/`B` = передний/задний конец. Индексы 0–3 относятся к L1, 4–7 к L2, 8–11 к L3, 12–15 к L4, 16–19 к L5, 20–21 к S1. Таким образом, оценка проводится по 11 анатомическим отрезкам, каждый с двумя концами.

Конвертация описана в [`tools/convert_buu_to_lumbar_coco.py`](../tools/convert_buu_to_lumbar_coco.py). Разбиение выполнено перемешиванием `random.Random(42)` с долями 0.8/0.1/0.1; идентификатор извлекается из имени файла до первого дефиса и проверяется на уникальность. Изображения доступны через символическую ссылку `data/LumbarCoco2000/images` на исходный каталог `LA`. Bbox строится по минимуму и максимуму координат 22 точек, расширяется по каждой стороне на 10% диапазона по соответствующей оси и ограничивается границами снимка. Запись COCO bbox имеет формат `[x, y, width, height]`; `area = width × height`. Этот bbox — аннотация для crop, а не предсказание отдельного детектора.

| Разбиение | JSON | Изображений / экземпляров | Размеченных точек |
|---|---|---:|---:|
| Train | `data/LumbarCoco2000/annotations/lumbar_keypoints_train.json` | 1600 / 1600 | 35 200 |
| Validation | `data/LumbarCoco2000/annotations/lumbar_keypoints_val.json` | 200 / 200 | 4400 |
| Test | `data/LumbarCoco2000/annotations/lumbar_keypoints_test.json` | 200 / 200 | 4400 |
| **Всего** | | **2000 / 2000** | **44 000** |

«Обучение на 2000 изображениях» означает использование набора объёмом 2000 снимков: градиенты вычислялись на **1600 train-снимках**; 200 снимков использовались для выбора checkpoint и ещё 200 — для итоговой оценки. Файлы train/val/test не пересекаются по идентификаторам. Клиническая или межцентровая независимость выборок этим не устанавливается.

## 3. Модель и входные данные

Использована top-down `TopdownPoseEstimator` из MMPose: входом служит снимок **с известным аннотированным bbox**, выходом — 22 координаты. Детектор bbox не обучался и в тесте не оценивался. Входной crop имеет размер **256 × 512 пикселей** (`width × height`). `PoseDataPreprocessor` переводит BGR в RGB и нормализует каналы с `mean=[123.675, 116.28, 103.53]`, `std=[58.395, 57.12, 57.375]`. Горизонтальный flip на тесте выключен (`flip_test=False`).

| Компонент | Фактическая настройка |
|---|---|
| Backbone | `CSPNeXt`, `arch=P5`, `expand_ratio=0.5`, `deepen_factor=0.67`, `widen_factor=0.75`, `out_indices=(4,)`, channel attention, SyncBN, SiLU |
| Инициализация backbone | Предобученные веса `cspnext-m_udp-aic-coco_210e-256x192-f2f7d6f6_20230130.pth` из OpenMMLab; загрузка `PretrainedInit` отражена в журнале. Это **не** обучение всей сети с нуля |
| Голова | `RTMCCHead`, 768 входных каналов, 22 выхода, feature map 8 × 16, kernel 7 |
| GAU | `hidden_dims=256`, `s=128`, `expansion_factor=2`, SiLU; `dropout_rate=0`, `drop_path=0`, без относительного смещения и positional encoding |
| Представление точек | `SimCCLabel`, `split_ratio=2`, `sigma=(6,9)`, `normalize=False`, `use_dark=False` |
| Функция потерь | `KLDiscretLoss`, `beta=10`, `label_softmax=True`, `use_target_weight=True` |

Голова для 22 точек настроена под текущую задачу; путь предобученных весов относится к backbone. Исходные bbox и координаты точек остаются в координатах снимка, а `TopdownAffine` преобразует их к входному crop.

## 4. Обучающий конвейер и random bbox

Последовательность train pipeline: `LoadImage` → `GetBBoxCenterScale(padding=1.15)` → **`RandomLumbarBBoxExpansion`** → `TopdownAffine(input_size=(256,512))` → `GenerateTarget(SimCCLabel)` → `PackPoseInputs`. Следовательно, базовый crop уже увеличен коэффициентом 1.15 относительно COCO bbox, а величины случайного расширения отсчитываются **от исходных ширины и высоты COCO bbox**, до этого padding. В результирующем конфиге нет унаследованного `RandomBBoxTransform`: дочерний конфиг заменяет весь train pipeline. Нет также flip, фотометрических искажений, MixUp или Mosaic.

Настройки пользовательского преобразования:

| Параметр | Значение и смысл |
|---|---|
| `apply_prob` | 0.8: для каждого train-образца есть 80% вероятности запустить расширение и поворот; иначе crop остаётся после `GetBBoxCenterScale` |
| `side_probs` | Для левой, правой, верхней и нижней стороны по 0.5, выбор сторон независимый |
| `expansion_ranges` | Для каждой выбранной стороны независимое равномерное значение от 0 до 0.5 исходной ширины (`left/right`) либо высоты (`top/bottom`) bbox |
| Если не выбрана ни одна сторона | Принудительно выбирается одна из четырёх, здесь равновероятно; ветвь аугментации не остаётся пустой |
| `rotation_range` | После расширения равномерно выбирается добавочный угол от −15° до +15° |
| `clip_to_image` | `True`: осевой прямоугольник после расширения обрезается по границам снимка |

Преобразование меняет `bbox_center`, `bbox_scale` и `bbox_rotation`, не переписывая исходные точки или исходный аннотированный bbox. После поворота видимые конечные GT-точки проецируются на оси повёрнутого crop; при необходимости масштаб увеличивается настолько, чтобы они помещались. `TopdownAffine` затем может ещё увеличить масштаб под отношение сторон 256:512; после поворота crop может пересечь край исходного снимка и получить padding при affine warping. Поэтому предел 50% относится к **сэмплируемому добавочному расширению каждой стороны**, а не гарантирует такой же предел итогового crop после проверки точек и приведения пропорций.

На validation и test применяется фиксированный pipeline: `LoadImage` → `GetBBoxCenterScale(padding=1.15)` → `TopdownAffine(256,512)` → `PackPoseInputs`. Случайного bbox и вращения при оценке нет. Для просмотра работы аугментации в данном запуске сохранено **20** сравнений в [`augmentation_comparisons/`](../work_dirs/rtmpose-m-lumbar-coco2000-randombbox-localpck/augmentation_comparisons/). Их создаёт диагностический hook на равных интервалах шага; это отдельные примеры train dataset, а не копии текущего minibatch и не дополнительный обучающий сигнал.

## 6. Определение Local PCK

Реализованная метрика называется `LocalPCK`, режим **`segment`**, порог **0.1**. Для каждого из 11 GT-отрезков (верхняя/нижняя пластинка L1–L5 и верхняя пластинка S1) вычисляется его длина в пикселях `L_s` между двумя GT-концами. Для каждого конца `i` этого отрезка берётся евклидова ошибка предсказания `e_i` **в координатах исходного снимка**. Точка засчитывается при `e_i ≤ 0.1 × L_s`. Поэтому нормировка у каждой точки определяется длиной **её собственного** анатомического отрезка, а не шириной/высотой bbox, размером crop или средней длиной по снимку.

В знаменатель включаются только отрезки с двумя видимыми конечными GT-точками, конечными координатами и положительной конечной длиной. Каждый валидный отрезок даёт **две** точки. Неконечная ошибка предсказания не засчитывается. Итоговая `PCK` — сумма засчитанных точек, делённая на сумму допустимых точек **по всему датасету**; это не среднее отдельных PCK по изображениям. Прямая проверка всех трёх COCO JSON показала: среди 22 000 отрезков нет невидимых концов, неконечных координат и нулевых длин. Поэтому каждый из 200 validation/test-снимков даёт в знаменатель все 22 точки, всего **4400** на каждом из этих разбиений.

Например, при длине GT-пластинки 100 пикселей допуск равен 10 пикселям для каждого её конца. Для другого отрезка длиной 50 пикселей допуск равен 5 пикселям. Метрика оценивает геометрическую локализацию, а не диагноз, точность в миллиметрах или работу детектора. `mode=image_mean` реализован в коде метрики, но в данном запуске **не использован**. COCO AP/AR и обычные `PCK@0.05` по bbox в этом запуске **не рассчитывались**.

## 8. Интерпретация и ограничения

Результат подтверждает высокую долю точек в пределах **локального, зависимого от длины пластинки** допуска на данном фиксированном разбиении BUU-LSPINE_2000 при подаче GT bbox. Он не характеризует качество автоматического поиска позвоночника, иной проекции, других учреждений и устройств, физическую ошибку в миллиметрах или диагностическую точность. Инициализация backbone предобучена на внешних данных; в данном запуске новой тренировочной информацией были 1600 боковых снимков BUU. Один seed и один test-прогон не дают оценки вариативности между повторными обучениями. Для дополнительных выводов понадобятся внешняя выборка, анализ ошибок по точкам и изображениям, пространственная калибровка снимков и, при необходимости, проверка межэкспертной разметки.
