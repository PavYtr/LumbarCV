# Аугментации поясничного отдела позвоночника

В этой директории находятся преобразования для top-down pipeline MMPose.
Каждый класс наследует `mmcv.transforms.BaseTransform` и регистрируется в
`mmpose.registry.TRANSFORMS`, поэтому в конфигурациях используется через
`dict(type='ИмяКласса', ...)`.

| Класс | Файл | Назначение |
| --- | --- | --- |
| `RandomLumbarBBoxExpansion` | [bbox.py](bbox.py) | Асимметричное расширение области кропа и случайный поворот |
| `RandomVertebraeCrop` | [vertebrae_crop.py](vertebrae_crop.py) | Кроп по размеченным точкам со случайными полями и наклоном позвоночника |
| `RandomVertebraeShift` | [vertebrae_shift.py](vertebrae_shift.py) | Сдвиг верхней части изображения вдоль выбранного межпозвонкового промежутка |
| `LumbarGridDistortion` | [grid_distortion.py](grid_distortion.py) | Нелинейная деформация изображения и точек по случайной сетке |
| `FullImageBBox` | [vertebrae_crop.py](vertebrae_crop.py) | Вспомогательное преобразование: bbox на всё изображение |

## Общие соглашения

- Координаты точек — `(x, y)` в пикселях исходного изображения; bbox —
  `(x_min, y_min, x_max, y_max)`.
- Преобразования рассчитаны на один top-down экземпляр. Для позвоночника
  используется 22 точки: для каждого L1–L5 последовательно `TF`, `TB`, `BF`,
  `BB`, затем `S1TF`, `S1TB`. Полный порядок задан в `KEYPOINT_NAMES`.
- У `RandomVertebraeCrop`, `RandomVertebraeShift` и `LumbarGridDistortion`
  при многоканальном `keypoints_visible` размеченность определяется первым
  каналом: значение `> 0` означает размеченную точку.
- `RandomLumbarBBoxExpansion` и `RandomVertebraeCrop` задают
  `bbox_center`, `bbox_scale`, `bbox_rotation`. Пиксели и исходные точки
  преобразует следующий `TopdownAffine`.
- `RandomVertebraeShift` и `LumbarGridDistortion` сразу меняют пиксели и
  координаты `keypoints`. Их нужно ставить до вычисления кропа,
  финального `TopdownAffine` и `GenerateTarget`.
- Все описанные ниже значения по умолчанию взяты из конструкторов классов.
  В конфигурациях экспериментов они могут быть переопределены.



## RandomVertebraeCrop

**Как работает.** Определяет исходный наклон по оси от середины верхней
пластины L1 к середине верхней пластины S1. Положительный угол означает,
что S1 расположен правее L1. Виртуально выравнивает эту ось по вертикали,
а затем задаёт случайный **целевой наклон**, равномерно выбранный из
`rotation_range`. Это целевой угол позвоночника, а не добавка к исходному.

Строит прямоугольник вокруг всех размеченных точек в новой ориентации.
Независимо выбирает четыре относительных поля из `expansion_ranges`.
Левое и правое поля умножаются на ширину области размеченных точек при
вертикальной оси позвоночника, верхнее и нижнее — на её высоту. Эти базовые
размеры измеряются до восстановления случайного наклона. К каждому полю
добавляется защитный отступ.

Параметры кропа сохраняются в исходной системе координат; изображение здесь
не обрезается и не поворачивается. При исходном угле `a` и целевом `b` класс
записывает `bbox_rotation = b - a`. Коррекция пропорций в `TopdownAffine`
может дополнительно расширить область, сохраняя размеченные точки.
Выход за исходное изображение допускается; при последующем warp возможны
чёрные поля.

| Гиперпараметр | По умолчанию | Значение и ограничения |
| --- | --- | --- |
| `statistics_file` | `None` | Путь к JSON со статистикой train-выборки. Нужен, если диапазоны не заданы явно |
| `expansion_ranges` | `None` | Словарь `left/right/top/bottom → (low, high)`, конечные числа, `0 <= low <= high`. При отсутствии берётся `(0, mean.margins_relative[side])` из JSON |
| `rotation_range` | `None` | Диапазон целевого наклона в градусах, конечные числа, `-90 < low <= high < 90`. При отсутствии берётся `(-m, m)`, где `m = mean.absolute_angle_deg` из JSON |
| `apply_prob` | `1.0` | Вероятность применения, от 0 до 1 |
| `safety_margin_px` | `2.0` | Неотрицательный конечный защитный отступ на каждой стороне, в исходных пикселях. Даже при `0` сохраняется малый численный запас против ошибок округления |

Без файла статистики нужно явно задать оба диапазона. Явные диапазоны имеют
приоритет над значениями из файла; сам переданный файл всё равно читается и
проверяется. JSON должен иметь `schema_version=1`, точный `keypoint_names`
и блок `mean` с положительным `count`. Подходящий файл создаёт
[collect_vertebrae_statistics.py](../tools/collect_vertebrae_statistics.py):

```bash
python tools/collect_vertebrae_statistics.py \
  --annotations data/LumbarCoco2000/annotations/lumbar_keypoints_train.json \
  --output reports/vertebrae_statistics_train.json
```

Статистика полей измеряется после виртуального выравнивания позвоночника
относительно повёрнутых границ **реального изображения**. Для каждой стороны
используется минимальный доступный зазор вдоль стороны области точек;
отрицательный зазор заменяется нулём. Средние относительные поля и средний
модуль угла вычисляются по корректным записям train-выборки.

Нужны ровно 22 точки `(1, 22, 2)` и соответствующая видимость; все размеченные
точки должны быть конечными. Четыре опорные точки L1 сверху и S1 должны быть
размечены, середина S1 должна находиться ниже середины L1. До вызова должен
быть рассчитан `bbox_center` формы `(1, 2)`, а `bbox_rotation` должен быть
нулевым. Совмещать с уже заданным другим поворотом нельзя.

Кроме геометрии кропа записывает `vertebrae_crop` с исходным углом,
выбранным целевым углом и относительными полями. Если применение пропущено,
сохраняет исходную геометрию, например кроп полного изображения.

Порядок: `LoadImage → FullImageBBox → GetBBoxCenterScale → RandomVertebraeCrop → TopdownAffine`.
Пример: [конфигурация vertebrae-crop](../configs/rtmpose-m_lumbar-coco2000_vertebrae-crop.py).

## RandomVertebraeShift

**Как работает.** С вероятностью `prob` выбирает один из пяти промежутков:
L1–L2, L2–L3, L3–L4, L4–L5 или L5–S1, каждый с вероятностью `1/5`.
По четырём точкам соседних пластин строит два средних положения между
соответствующими концами пластин. Прямая через них разделяет изображение;
её отрезок задаёт направление и базовую длину сдвига.

Анатомически верхняя полуплоскость вместе со всеми лежащими в ней точками
переносится параллельно этой прямой. Модуль сдвига равномерно выбирается
от нуля до `max_shift_ratio × длина отрезка`; знак выбирается равновероятно.
Нижняя полуплоскость остаётся на месте, точки точно на линии раздела относятся
к ней. Соответствие концов пластин определяется обозначениями `F/B`,
а не сортировкой координат, что учитывает отражённые и наклонённые снимки.

Если сдвиг выведет размеченные точки за изображение, весь вектор пропорционально
уменьшается. Пиксели сдвигаются с линейной интерполяцией и чёрным заполнением
за краями; на линии раздела интерполяция нормируется по верхней части,
чтобы не смешивать её с нижней и не создавать тёмный шов.

| Гиперпараметр | По умолчанию | Значение и ограничения |
| --- | --- | --- |
| `prob` | `0.5` | Вероятность попытки применения, конечное число от 0 до 1 |
| `max_shift_ratio` | `0.25` | Максимальный модуль сдвига в долях длины отрезка раздела. Конечное неотрицательное число; `0` отключает сдвиг, `0.25` означает до 25% в любую сторону |

Ожидает `img`, `keypoints` формы `(1, 22, D)`, `D >= 2`, и видимость формы
`(1, 22)`, `(1, 22, 1)` или `(1, 22, 2)`. Меняет только `img` и xy точек;
дополнительные координаты, видимость, bbox и исходные аннотации сохраняются.
Кроп следует рассчитывать после сдвига по обновлённым точкам либо использовать
полное изображение.

Если у выбранного промежутка отсутствует разметка четырёх опорных точек или
геометрия вырождена, преобразование пропускается без выбора другого промежутка.
Пропуск также возможен при некорректных исходных размеченных точках или
невозможности безопасного сдвига. Поэтому фактическая доля изменённых примеров
может быть меньше `prob`. После `TopdownAffine` применять нельзя.

Порядок: `LoadImage → RandomVertebraeShift → FullImageBBox → GetBBoxCenterScale → RandomVertebraeCrop → TopdownAffine`.
Примеры: [shift-crop](../configs/rtmpose-m_lumbar-coco2000_vertebrae-shift-crop.py)
и [shift-crop-modified](../configs/rtmpose-m_lumbar-coco2000_vertebrae-shift-crop-modified.py).

## LumbarGridDistortion

**Как работает.** Обёртка над `albumentations.GridDistortion`: делит координатные
оси на участки и случайно меняет их масштаб, формируя сетку нелинейной
деформации. По одной геометрии преобразует изображение и координаты точек.
Размер холста остаётся прежним. Вероятность применения контролируется
NumPy, а генератор Albumentations получает новый seed при каждом применении,
чтобы учитывать seed работников dataloader MMPose.

| Гиперпараметр | По умолчанию | Значение |
| --- | --- | --- |
| `num_steps` | `5` | Число участков сетки по каждой оси. Размеры изображения должны быть не меньше этого значения |
| `distort_range` | `(-0.05, 0.05)` | Диапазон случайных отклонений масштаба участков от единицы. В API Albumentations 2.0.8 передаётся как `distort_limit` |
| `normalized` | `True` | Нормировать сетку так, чтобы её границы оставались в пределах изображения |
| `p` | `0.5` | Вероятность применения, конечное число от 0 до 1 |
| `interpolation` | `cv2.INTER_LINEAR` | Метод интерполяции пикселей OpenCV |
| `border_mode` | `cv2.BORDER_CONSTANT` | Способ обработки координат за границами изображения |
| `fill` | `0` | Значение заполнения при постоянной границе; по умолчанию чёрный |
| `keypoint_remapping_method` | `'direct'` | Метод переноса точек Albumentations: `'direct'` — прямой поиск соответствия, `'mask'` — через растровые маски |

Кроме `p`, параметры сетки передаются на проверку Albumentations.
Реализация проверяет наличие необходимых аргументов API; при несовместимости
предлагает `albumentations==2.0.8` и выдаёт ошибку.

Требует конечные вещественные `keypoints` формы `(1, 22, D)`, `D >= 2`,
конечную видимость формы `(1, 22)`, `(1, 22, 1)` или `(1, 22, 2)` и `img`.
Все размеченные точки до деформации должны находиться внутри изображения.
Если `bbox` присутствует, он должен совпадать с полным холстом
`[[0, 0, width, height]]`; его можно задать через `FullImageBBox`.

Количество и порядок точек сохраняются. Дополнительные координатные и
visibility-каналы сохраняются, кроме обнуления всей видимости точек,
оказавшихся вне кадра. Неразмеченные исходные заглушки вне изображения
сохраняют свои координаты. Bbox полного холста не меняется.

При методе `'mask'` растровая точка может потеряться: тогда пробуется до трёх
случайных сеток. Если все попытки неудачны, выдаётся предупреждение и исходный
пример возвращается без изменений. При `'direct'` некорректный результат
переноса вызывает ошибку.

Порядок: `LoadImage → FullImageBBox → LumbarGridDistortion → GetBBoxCenterScale → RandomVertebraeCrop → TopdownAffine`.
`RandomVertebraeCrop` только задаёт будущую геометрию, поэтому его перестановка
перед деформацией сама по себе не даст деформацию уже выровненного снимка.
После финального `TopdownAffine` применять нельзя.
Пример: [конфигурация grid-distortion-crop](../configs/rtmpose-m_lumbar-coco2000_grid-distortion-crop.py).

## FullImageBBox

Детерминированное вспомогательное преобразование без собственных
гиперпараметров. По `results['img'].shape` задаёт:

- `bbox = [[0, 0, width, height]]`;
- `bbox_score = [1.0]`;
- `bbox_rotation = [0.0]`.

Удаляет старые `bbox_center` и `bbox_scale`, чтобы следующий
`GetBBoxCenterScale` рассчитал их заново. Не использует GT-точки и может
применяться как при обучении, так и при валидации/инференсе. Самостоятельно
не меняет изображение и координаты точек.

## Подключение в конфигурации

Для регистрации классов импортируйте соответствующие модули:

```python
custom_imports = dict(
    imports=[
        'augmentations.bbox',
        'augmentations.vertebrae_crop',
        'augmentations.vertebrae_shift',
        'augmentations.grid_distortion',
    ],
    allow_failed_imports=False,
)
```

`LumbarGridDistortion` не экспортируется в `augmentations/__init__.py`, поэтому
для него необходимо явно импортировать `augmentations.grid_distortion`.
Всем преобразованиям нужны NumPy, MMCV и MMPose; сдвигу и деформации также
нужен OpenCV, а `LumbarGridDistortion` — совместимый Albumentations.
